v1.4.0Local-first desktop app

Direct an AI lab, don’t chat with an assistant.

Elenchia is a desktop app where you staff a lab of AI agents, point them at a research question, and approve what they do. They argue, design experiments, run them and grade the evidence. You are the ethics and approval layer.

Agents run on local models through LM Studio or Ollama. Your questions, data and the agents’ reasoning stay on your machine.

01

A run, step by step

A run is seven steps. Steps two to six loop, up to three rounds, until the critic and the statistician have no open objections. Three of the steps are gates: nothing happens there without your decision.

03

What the code enforces

These are rules in the orchestrator, not requests in a prompt. A model that ignores its brief still cannot do these things.

Approvals are specific
You approve a concrete spec: a code diff against the previous experiment, a runtime estimate, the statistician’s plan and a risk label. Never a vague “continue?”.
Any agent can flag. Only you can clear.
A flag stops the run until you decide. Overriding one needs a written reason, which is logged.
Roles stay adversarial
The critic can only add objections. The experimentalist’s output is never read as a grade. The statistician’s grade is clamped to inconclusive if nothing was executed.
Numbers come from executed code
Agents exchange schema-checked JSON. Results are parsed from the sandbox’s output line, never from what an agent says about them.
Tentative is the default
A finding only reaches “established” if you accept it, it links to an executed result, the evidence is moderate or strong, and the critic conceded. Promotion can never establish a claim on its own.
Everything is replayable
The event log is hash-chained SQLite with triggers that reject updates and deletes. Every screen is a reduction over it, so you can scrub to any moment. Prompts, model names, temperatures and seeds are stored.
04

Models and tools

Local first. Anything that leaves your machine is opt-in, shows you exactly what will be sent, and asks every time.

LM Studio

The default. Load an instruct model (7B or larger works best), start the server on the Developer tab, and Elenchia lists your models and warns when one won’t fit your GPU.

default

Ollama

Detected automatically on port 11434.

local

OpenAI-compatible API

OpenAI, OpenRouter, Groq or any server that speaks the same API. Agents on it send their prompts, including your question, to that provider, and a warning says so.

cloud · optional

Paper and web search

OpenAlex and Semantic Scholar for papers, falling back to the web. Agents ask to search; you edit and approve each query.

opt-in

Built-in browser

Opens one public page in a throwaway Edge or Chrome profile: no logins, downloads blocked, local addresses refused. You watch it in the app.

opt-in

Parallel work

Several hypotheses are tested at once when your GPU has room for the models. A CPU-only machine, or a full GPU, stays one at a time.

auto

Export and import

PDF, Word, Markdown, HTML, plain text, CSV, or a .elenchia file you can open again to view the notebook.

built in

Python sandbox

Experiments run as Python in an isolated process with no network. Without Python installed, the demo lab falls back to a built-in kernel and says so.

optional
05

Install

Installers for each platform are attached to the latest release.

  1. Run the installer. Windows shows “Windows protected your PC” because the build is unsigned: choose More info, then Run anyway.
  2. Windows 11 already includes the WebView2 runtime the app uses.
  1. Pick Apple Silicon (M1 and later) or Intel, open the disk image and drag Elenchia to Applications.
  2. The build is unsigned, so macOS blocks the first launch. Right-click the app and choose Open, or clear the quarantine flag:
$ xattr -dr com.apple.quarantine /Applications/Elenchia.app
  1. AppImage: make it executable and run it.
  2. Debian or Ubuntu: install the .deb. Either needs WebKitGTK 4.1 (libwebkit2gtk-4.1), which current distributions ship.
$ chmod +x Elenchia_*_amd64.AppImage && ./Elenchia_*_amd64.AppImage
$ sudo dpkg -i Elenchia_*_amd64.deb
  1. Install Rust (stable). On Windows that means the MSVC toolchain; on Linux, the WebKitGTK and GTK development packages.
  2. There is no Node toolchain: the interface is plain HTML, CSS and JavaScript.
$ git clone https://github.com/realaaravdas/Elenchia.git
$ cd Elenchia
$ cargo run --manifest-path src-tauri/Cargo.toml
First run
  1. Start a model server. In LM Studio, download an instruct model, open the Developer tab and switch Start Server on. Without one, Elenchia runs the scripted demo lab so you can see the whole flow.
  2. Open the app. The top bar shows how many models it found. Assign one to each agent in the Lab designer, or press the auto-assign button.
  3. Ask a question. Press N, type a research question, and approve the first gate. The status badge says when it is running and when it is waiting on you.
06

Limits, stated plainly

  • The sandbox is process isolation, not an OS container. Generated code runs in a separate Python process with a scrubbed environment, no network and a time limit, but you should still read code before you approve it.
  • The newer features have had less real-world testing. The browser, online search, cloud models and parallel mode have mostly been exercised against the scripted lab, mock servers and one local 12B model. Report anything that misbehaves.
  • Search engines block automated browsers. Google and DuckDuckGo show bot challenges, and Elenchia does not try to get around them. For full web search, point it at your own SearXNG.
  • Custom roles are stored and drawn, but only the six built-in roles are scheduled.
  • Refusal rules are narrow. A short built-in list stops clearly harmful framings before any model is called; everything subtler relies on agent flags and your ethics gate.
  • Installers are unsigned, so each operating system warns on first launch.
